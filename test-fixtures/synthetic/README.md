# Portable synthetic import fixtures

These files are generated test data. They contain no rows copied from CFPS,
CGSS, or another real survey, and tests must not describe them as real survey
data.

## `stata-import.synthetic.dta`

Generated with pandas 2.2.3 using `DataFrame.to_stata(..., version=118,
write_index=False)`. It has three observations and these columns:

| countyid | provname | income |
| ---: | --- | ---: |
| 110101 | North Province | 12.5 |
| 120102 | Central Province | 18.0 |
| 310104 | South Province | 22.75 |

Variable labels are `Synthetic county code`, `Synthetic province name`, and
`Synthetic income`.

## `excel-codebook.synthetic.xls`

Generated with the project's `xlsx` package by writing a one-sheet workbook
with `bookType: "biff8"`. The `Synthetic codebook` sheet has columns
`indicator`, `label`, and `value`, with rows `access / Access score / 1`,
`income / Income score / 2`, and `health / Health score / 3`.

The tests read these named paths relative to `src/lib/io.test.ts`, so they work
from any checkout location without external datasets.

## Stata edge-case files

`stata-tag-in-string-{117,118,119}.synthetic.dta` and
`stata-strl.synthetic.dta` are copies of independently generated pandas 2.2.3
fixtures from the repository's `audit/` directory (`make-fixtures.py`). The
first three each have a text value equal to `</data>` to verify that data is
located from Stata's map offsets. The strL file has two 2,100-character text
values. The original audit files remain unchanged as historical evidence.

`stata-whitespace.synthetic.dta` is a separate pandas 2.2.3 version 118 fixture
with leading and trailing spaces in a text value. It checks that source string
whitespace survives import.

`stata-large-measure.synthetic.dta` is a separate pandas 2.2.3 version 118
fixture with numeric measure values above JavaScript's safe integer limit. It
checks that Stata numeric measures remain numeric rather than being converted
to text.

`stata-value-label-tags.synthetic.dta` is a copy of the independently
pandas-generated, valid version 118 file in
`.superpowers/sdd/reliability/value-label-tags.dta`. One value label contains
the byte strings `</lbl>` and `</value_labels>`; the copy is used to verify
that the map and table length, rather than embedded text, delimit the label.

`stata-latin1-117.synthetic.dta` is generated by pandas 2.2.3 using version
117's Latin-1 text encoding and contains `café`. It verifies that unsupported
legacy text encodings are rejected with guidance instead of silently replaced.
Stata text fields currently require valid UTF-8; re-export older encodings as
Unicode version 118 or 119 before import.
