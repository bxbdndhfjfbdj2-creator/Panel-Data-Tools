# 架构与方法契约

## 运行结构

- `src/components/` 提供五步交互：数据、筛选、体系、聚合、结果。状态由 `src/lib/store.ts` 管理。
- `src/lib/io.ts`、`csv.ts` 与 `dta.ts` 负责 CSV/TSV、Excel 和 Stata 输入；`catalog.ts` 保留宽表字段目录。
- `src/lib/engine.ts` 负责筛选统计、权重、得分、排名、分组汇总、方法对照和影响诊断；数值方法在 `stats.ts`、`transform.ts`、`ahp.ts`、`npar.ts` 等模块。
- `src/lib/persist.ts` 校验工作区 JSON 并读写浏览器存储；`report.ts` 与 `scripts.ts` 生成报告、得分和 R/Stata 草图。
- 认证、数据库、平台桥接位于 `src/lib/auth/`、`server/` 与 Vite 插件。当前本地环境将 `VITE_AUTH_ENABLED` 设为 false，部署平台可覆盖。分析数据路径不调用业务上传接口。

## 分析口径

工作流必须显式保留数据列与指标元数据的分离。列目录中的稀疏数值字段可以纳入；方向、维度、权重和元标签不应覆盖原始观测值。筛选规则用于提示和选择，不隐式删除数据。正式计分只使用选中且已归维的指标。

当前标准化与缺失策略：极差标准化输出 0–100；Z 分数指数映射到均值 50、标准差 10；TOPSIS 使用其自身方向调整与极差变换。缺失策略为整行删除、列均值填补或按行可用指标重标权重；TOPSIS 不支持可用指标模式。缩尾可选 0%、1% 或 5%，对数变换可选无、ln 或 ln(1+x)。

熵权、变异系数、CRITIC、主成分载荷等客观权重在维度内计算，维度权重再合成目标层。AHP 是成对判断产生的维度权重。中位数与切尾均值是非加性聚合，结果不提供可加的指标贡献分解。分组均值在有抽样权重时使用加权均值并显示 Kish 有效样本量；个体得分与排名不因抽样权重而改变。

面板时间窗口使用数值年份；“各实体最新观测”是每个实体各自的最新实际年份，因此不同实体可能对应不同年份。时期均值视图先汇总入选时期的个体结果。方法对照、留一法与重抽样应使用同一结果视图。36 次重抽样仅提供敏感性范围，显示有效次数和停用原因，不解释为完整置信区间。

## 结果解释与复现

导出的报告记录实际配置、筛选阈值、方向/变换、角色列、维度与指标权重、当前视图及数据哈希。哈希用于检测本次配置输入的一致性，不是数字签名或来源认证。报告中的 R/Stata 文件是便于继续分析的草图，不承诺逐步等价复现。

自动构念、平行分析、旋转、α/CITC、KMO、AVE/CR 近似仅供探索性检查。此应用不实现完整 CFA/SEM、复杂抽样方差、多重插补、因果识别或正式推断。指标方向推断也需要用户核对。

## 质量门禁

`npm test` 运行业务与平台测试；`npm run typecheck`、`npm run lint`、`npm run audit:deps` 与 `npm run build` 分别检查类型、代码风格、依赖公告和产物。`.github/workflows/quality-gates.yml` 在 Node 22、24 上执行这些步骤。
