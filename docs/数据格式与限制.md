# 数据格式与限制

## 支持格式

| 格式 | 行为与限制 |
| --- | --- |
| CSV / TSV | 浏览器读取文本，自动识别分隔符；重复表头加 `_2` 等后缀，空表头命名“列N”；文本 ID 与大整数编号按原文保留。 |
| Excel `.xlsx` / `.xls` | 使用 `xlsx` 模块 API；默认选择有效行数最多的工作表，不合并多个工作表；公式读取缓存值，不计算公式。 |
| Stata `.dta` | 支持 Stata 117–119；保留值标签元数据与数值分离，超出当前 UTF-8 兼容能力的旧编码文件会提示重新导出。 |

方案 JSON 可在“方案”菜单导入/导出。导入时会校验版本、枚举、数值、字段引用与目录引用。文件导入以宽表为主；系统不会自动识别多个文件之间的连接关系。

## 缺失值与编码

物理空单元格与空文本作为缺失。文本 `NA`、`N/A`、`.`、`97`、`99` 等不会按通用问卷惯例自动改成缺失；请在源文件中先将特殊编码改为空值，或确保其被识别为文本/元数据。Stata value labels 只用于显示元信息，不把 97/99 等底层值自动覆盖成标签。导入数字列时非编号字段会尝试数值解析；编号列保留前导零和不安全整数的原始文本。

## 资源上限

- 任意单文件不得超过 120 MiB。
- Excel 工作簿最多 100 个工作表；每张有数据的工作表最多 100,000 行、500 列和 2,000,000 个矩形单元格。矩形单元格数按声明的单元格范围估算，稀疏表也会受限。
- 工作流最多纳入 80 个指标列；UI 候选目录可以显示更多列，分析前仍须选择。
- 工作方案写入浏览器 `localStorage`，容量由浏览器与当前站点额度决定，不能保证保存大型工作簿。保留 JSON 文件备份。

这些阈值能避免常见误操作和过大的工作表展开，但 XLS/XLSX 解包仍在当前浏览器主线程内由依赖执行。文件大小与工作表范围检查不能完全防止特制压缩文件造成的 CPU/内存耗尽。只导入可信来源的工作簿；如需面对不可信文件，请先在隔离环境中清理或转换。

## Excel 依赖风险记录（2026-10-08）

`xlsx@0.18.5` 的 npm 官方包受到 GHSA-4r6h-8v6p-xvw6（Prototype Pollution）与 GHSA-5pgg-2g8v-p4x9（ReDoS）公告影响；npm registry 的 `xlsx` 最新版本仍为 0.18.5，未提供修复版本。项目将 npm alias `xlsx: npm:@e965/xlsx@0.20.3`，保留旧 `import "xlsx"` API 与 `.xls/.xlsx` 测试兼容，同时将包更新到公告范围之外的 0.20.3。来源： [GHSA-4r6h-8v6p-xvw6](https://github.com/advisories/GHSA-4r6h-8v6p-xvw6)、[GHSA-5pgg-2g8v-p4x9](https://github.com/advisories/GHSA-5pgg-2g8v-p4x9)、[`@e965/xlsx` npm 包](https://www.npmjs.com/package/@e965/xlsx)、[SheetJS](https://sheetjs.com/)。准确版本与 tarball integrity 锁在 `package-lock.json`。

`@e965/xlsx` 是兼容发布包而非 npm 上游 `xlsx` 名称下的官方修复版；发布维护者的近期活跃度低于活跃的解析器替代品，因此仍需在更新周期中重新评估长期维护性。当前加了文件大小、工作表数量、行列及矩形范围上限；这些检查在工作簿被解析后执行，不能替代 Worker 隔离。跟踪上游安全更新，若要迁移到不同解析器，必须保留旧 `.xls` 兼容决策并运行合成与真实格式回归。

## 隐私与网络

导入、分析及工作方案处理由浏览器端应用代码执行；当前业务路径不发送数据集到后端。自动恢复会把整个工作区写入本机站点 `localStorage`。页面仍请求部署托管平台资源，并请求 Google Fonts；登录启用时会调用部署中配置的认证服务。网络服务可看到常规连接元数据，托管平台可能记录访问日志。请勿将“浏览器端计算”理解为页面完全离线，也不要将敏感数据导入到不受控浏览器/设备。
