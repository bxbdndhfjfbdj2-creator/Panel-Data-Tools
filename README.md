# 衡策 Hengce

衡策是面板数据与问卷数据的浏览器端工作台，用于指标筛选、层级结构整理、维度内赋权、聚合和结果稳健性检查。它面向探索和方案比较，不替代正式测量模型、复杂抽样推断或因果分析。

## 本地运行

需要 Node.js 22 或 24 与 npm。安装依赖后启动开发服务器：

```sh
npm ci
npm run dev
```

质量门禁与生产构建：

```sh
npm test                 # 业务 + 平台测试
npm run test:business
npm run test:platform
npm run typecheck
npm run lint
npm run audit:deps
npm run build
npm run preview
```

`npm run build` 先生成 Vite/Nitro 产物，再调用数据库迁移脚本；数据库未配置时迁移脚本按项目平台约定跳过。CI 对 Node 22 和 24 执行安装、测试、类型检查、lint、依赖审计与构建。生产部署由项目托管平台完成，需在平台上设置其构建环境变量与服务配置；不要把 `.grok/app-env.json` 当作密钥文件。

开发服务器默认使用 `.grok/app-env.json` 中的 `VITE_AUTH_ENABLED=false`。平台部署可以覆盖这个值；启用登录时会涉及认证服务和 cookie/session，请按部署平台的认证配置评估网络请求与隐私边界。

## 导入与保存

- 可导入 CSV、TSV、Excel `.xls` / `.xlsx` 和 Stata 117–119 `.dta`；Excel 默认按工作表 `!ref` 声明范围的行数选择，稀疏表可能因此被优先，导入前请清理无关范围。列目录可搜索并选择，最多纳入 80 列。
- 单文件上限为 120 MiB。Excel 另限制最多 100 个工作表、每表 100,000 行、500 列、2,000,000 个矩形单元格。超限时请先在原软件裁剪文件。
- 空单元格按缺失处理；字符串如 `NA`、`N/A`、`97`、`99` 不会被统一改成缺失。Stata 值标签作为元数据保留，不替换底层数值。CSV/TSV 保留编号文本、前导零、重复列名和空表头（空表头会命名为“列N”）。
- 当前支持宽表。多工作表不会合并，Excel 公式按文件中缓存的单元格值读取，不执行公式。复杂宏、外部链接、图表和格式不进入分析。
- 工作方案自动保存在当前浏览器配置的 `localStorage`，并可导入/导出 JSON；清理网站数据、换浏览器或隐私窗口会影响恢复。得分/报告导出为独立文件。浏览器存储空间有限，较大数据集可能无法保存，应用会显示保存错误。

## 隐私与网络边界

导入数据的解析、筛选和统计计算由当前浏览器完成，应用业务代码不会把分析数据或方案上传到服务端。方案会持久化到当前浏览器 `localStorage`。页面会加载托管平台提供的运行资源（包括平台脚本/图标等），并向 Google Fonts 请求字体；这些请求会发送必要的连接元数据，例如 IP 地址和请求头。托管平台自身也可能记录访问日志。若部署时启用登录，认证请求还会与配置的认证服务通信。该说明不涵盖浏览器扩展、设备备份或托管方日志策略。

## 当前限制与路线图

当前指数用于探索性比较；自动构念与 α / AVE / CR 仅为辅助诊断，不是完整 CFA。抽样权重只进入已声明的加权环节，不代表复杂抽样方差估计；敏感性重抽样范围不等于置信区间。R/Stata 导出是分析草图，不能保证与浏览器实现等价。

后续优先工作：把耗时计算移入可取消 Worker 并建立性能基准；为大型方案改用带版本管理的 IndexedDB；增加可预览的导入向导；按面板/问卷目标提供固定基期或测量模型选项；评估复杂抽样与多重插补方法。
